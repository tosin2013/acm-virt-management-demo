== Part 1 -- The Problem with Cluster-Admin

=== Know

_The traditional Kubernetes administrative model forces organizations into granting `cluster-admin` privileges to facilitate deployment and infrastructure scaling. This violates the principle of least privilege and introduces systemic risk -- a leaked credential or a rogue insider with cluster-admin can destroy the entire platform._

**Business Challenge:**
Development teams need to deploy VM workloads across multiple clusters. The path of least resistance is granting `cluster-admin` to everyone who needs to deploy. This creates:

* *Audit blind spots* -- cluster-admin actions are broadly scoped and difficult to attribute
* *Blast radius* -- a compromised cluster-admin credential can delete namespaces, drain nodes, or destroy the entire cluster
* *Compliance violations* -- regulatory frameworks (NIST, PCI-DSS, HIPAA) require least-privilege access models

**Technical Solution:**
RHACM provides the `open-cluster-management:subscription-admin` ClusterRole that allows users to create Git Subscriptions deploying resources across multiple namespaces -- without granting `cluster-admin`.

Combined with OpenShift GitOps (ArgoCD), the Git repository becomes the immutable single source of truth. Developers push to Git; ACM Subscriptions sync to clusters. No human ever runs `oc apply` directly against a production cluster.

=== Show

NOTE: Ensure you are on the **Hub cluster terminal** and logged into OpenShift. If unsure, run `oc whoami` to verify. See xref:02-details.adoc#_connecting_to_clusters[Connecting to Clusters] for setup.

* Review the current RBAC setup -- note that the demo-deployer user does NOT have cluster-admin:
+
[source,role="execute"]
----
oc auth can-i --list --as=demo-deployer | grep -E "cluster-admin|managedcluster"
----
+
Expected: no results -- this user has no cluster-wide destructive permissions.

* Apply the subscription-admin binding from the rbac/ directory:
+
[source,role="execute"]
----
oc apply -f rbac/subscription-admin-binding.yaml
----

* Verify the binding was created:
+
[source,role="execute"]
----
oc get clusterrolebinding gitops-subscription-admin -o wide
----

== Part 2 -- Deploy a VM Via Git Subscription

=== Know

_With `subscription-admin` bound, a user can create RHACM Subscriptions that deploy resources from a Git repository to managed clusters -- without cluster-admin. This is a real deployment: an actual VM will boot on the managed cluster, deployed entirely through Git._

The subscription model provides:

* *Declarative deployment* -- desired state is defined in Git, not in CLI commands
* *Automatic sync* -- changes pushed to Git are automatically detected and applied
* *Audit trail* -- every deployment change is a Git commit with author, timestamp, and diff
* *Cross-cluster reach* -- a single Subscription deploys to every cluster matching the Placement

=== Show

* Create a dedicated namespace for the subscription deployment, bind the ManagedClusterSet so the Placement can select clusters, and create the Placement:
+
[source,role="execute"]
----
oc create namespace vm-subscription-demo

cat <<EOF | oc apply -f -
apiVersion: cluster.open-cluster-management.io/v1beta2
kind: ManagedClusterSetBinding
metadata:
  name: virt-clusters
  namespace: vm-subscription-demo
spec:
  clusterSet: virt-clusters
---
apiVersion: cluster.open-cluster-management.io/v1beta1
kind: Placement
metadata:
  name: virt-subscription-placement
  namespace: vm-subscription-demo
spec:
  predicates:
    - requiredClusterSelector:
        labelSelector:
          matchLabels:
            virtualization-enabled: "true"
EOF
----

* Create a Channel pointing to the demo Git repository and a Subscription that deploys a Fedora VM running nginx from the `subscriptions/vm-demo-nginx/` path:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: apps.open-cluster-management.io/v1
kind: Channel
metadata:
  name: acm-virt-demo-channel
  namespace: vm-subscription-demo
spec:
  type: Git
  pathname: https://github.com/tosin2013/acm-virt-management-demo.git
---
apiVersion: apps.open-cluster-management.io/v1
kind: Subscription
metadata:
  name: vm-nginx-subscription
  namespace: vm-subscription-demo
  annotations:
    apps.open-cluster-management.io/git-path: subscriptions/vm-demo-nginx/
    apps.open-cluster-management.io/git-branch: main
spec:
  channel: vm-subscription-demo/acm-virt-demo-channel
  placement:
    placementRef:
      name: virt-subscription-placement
      kind: Placement
EOF
----

* Verify the Subscription is propagating:
+
[source,role="execute"]
----
oc get subscription vm-nginx-subscription -n vm-subscription-demo
----
+
Wait for the `PHASE` to show `Propagated`.

== Part 3 -- Verify the VM is Running

=== Know

_The most compelling part of this demonstration is proving that a real VM booted on the managed cluster -- deployed entirely through Git, by a user who never had cluster-admin. The VM namespace, the VirtualMachine, and the Service were all created by the ACM Subscription controller._

=== Show

* SSH to the managed cluster bastion:
+
[source,role="execute",subs="attributes+"]
----
{student_1_ssh_command}
----
+
Password: `{student_1_bastion_ssh_password}`

* Verify the VM is running:
+
[source,role="execute"]
----
oc get vm,vmi -n vm-subscription-demo
----
+
Expected: `nginx-subscription-vm` shows `Running` with `READY: True`.

[TIP]
====
The VM uses a container disk (`quay.io/containerdisks/fedora:latest`) with cloud-init installing nginx. The VM boots in about 60-90 seconds; nginx installation takes an additional minute. If the VM is not yet running, wait a moment and re-check.
====

== Part 4 -- Proving Non-Admin Deployment Works

=== Know

_The final proof: the user who deployed a running VM across the fleet cannot perform destructive cluster operations. Productivity and security are not mutually exclusive._

=== Show

* Verify the deployer cannot delete managed clusters:
+
[source,role="execute"]
----
oc auth can-i delete managedclusters --as=demo-deployer
----
+
Expected output: `no`

* Verify the deployer cannot destroy managed cluster sets:
+
[source,role="execute"]
----
oc auth can-i delete managedclustersets --as=demo-deployer
----
+
Expected output: `no`

* Verify the deployer cannot delete nodes:
+
[source,role="execute"]
----
oc auth can-i delete nodes --as=demo-deployer
----
+
Expected output: `no`

[IMPORTANT]
====
**Key message for the customer:** "This user just deployed a running VM to a managed cluster via Git -- without cluster-admin. The VM is serving traffic right now. But that same user cannot delete managed clusters, cannot destroy cluster sets, and cannot remove nodes. Git is the single source of truth, not human CLI access. This is the zero-trust deployment model."
====

[NOTE]
====
The `subscription-admin` role grants the permissions needed for cross-namespace Git deployments, but does NOT grant cluster lifecycle destruction (`delete managedclusters`, `delete managedclustersets`). Module 8 demonstrates how to further restrict even these operational users from cluster destruction.
====

== Key Takeaways

* `subscription-admin` enables cross-namespace VM deployment without `cluster-admin`
* A real VM was deployed, booted, and served traffic -- entirely through a Git Subscription
* Git becomes the immutable audit trail for all deployment changes
* RHACM Subscriptions provide automatic sync from Git to managed clusters
* Developers never need direct CLI access to production clusters
* Productivity and security are complementary, not competing concerns
